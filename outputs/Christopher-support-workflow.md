# Christopher Support App Workflow

This document describes the workflow to build a mobile-friendly support app for Christopher using the same voice generation infrastructure used for the podcast.

## Goal
Create a system where Christopher can type or speak what is wrong, and the app responds as a chosen family member (Mom/Dad/Callie/Gracie) with:

- Text generated by Claude API in the chosen family member’s style
- Local TTS converting text → audio (no ongoing ElevenLabs cost)
- Seed‑VC converting the audio into the family member’s voice using reference clips
- Streaming audio back to the client (mobile/web)

## Key Components

### 1) Reference Voice Clips (One-Time, ElevenLabs)

- Generate reference voice clips for each character/family member.
- These clips are used by Seed‑VC as the *target voice* for conversion.
- Existing script: `scripts/generate_reference_voices.py`

### 2) Claude API for Response Text

- Send user input + persona instructions to Claude.
- Receive a text response in the voice/style of the target family member.

### 3) Local TTS + Seed‑VC Conversion

1. Use local open-source TTS to turn Claude text into base audio (neutral voice).
2. Run Seed‑VC using the reference voice clip to convert the base audio into the target family member’s voice.

Existing conversion script: `scripts/convert_voice.py`

### 4) Server + Mobile/Web Client

- Host a server (FastAPI/Flask) that accepts requests:
  - `POST /api/respond` { persona, message }
  - returns: { text, audioUrl }
- Serve audio files via a static endpoint.
- Client plays the audio in the browser/mobile webview.

### 5) Caching for Speed

- Cache Claude text responses for identical (persona + input) pairs.
- Cache generated audio for identical (persona + text) pairs.
- Use a hash-based key (e.g., SHA-256) to store and retrieve cached results.

## Scaling to Other Families

- Use a per-family config directory:
  - `data/families/<familyId>/voices/`
  - `data/families/<familyId>/config.json`
- Store reference clips, persona prompts, and settings per family.
- The same server code can support multiple families by switching configs.
